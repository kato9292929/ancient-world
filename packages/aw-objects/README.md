# aw-objects

遺物の3Dビューア。第一の対象は **Weld-Blundell Prism**（四面の角柱、中央に軸穴、回して読む構造）。

## これは模型である

**実物のスキャンではなく、記録された寸法から起こした模型**。実物のスキャンデータが公開されて
いるかは未確認で、サンドボックスからも確認できないため、寸法から形状をコードで生成している。
この趣旨のラベルを画面の初期表示に常時出す（折りたたみやツールチップに隠さない）。

**刻文は再現していない。** 楔形文字の配置を推測で描くことになるため、面には欄の区切りだけを示し、
テクスチャは無地・簡略な陰影にとどめる。

スキャンが後から入手できたら差し替えられるよう、**形状の生成部分（`src/geometry.ts`）と表示部分
（`src/prism.ts` / `src/viewer.ts`）を分けてある。**

## 寸法の出所

記録された寸法（Weld-Blundell Prism）:

| 項目 | 値 | 出所 |
|---|---|---|
| 高さ | 約20cm | 記録あり |
| 幅 | 約9cm | 記録あり |
| 面 | 4面・各面に2欄 | 記録あり |
| 軸穴 | 中心を貫通 | 存在は記録あり |

**記載のない寸法は推測で埋めない。** このモデルでの扱い（`src/geometry.ts` のコメントにも明記）:

- **断面の奥行き**は記録に無い。「四面の角柱」で幅のみ記載のため、断面は一辺 = 幅 の正方形として
  扱う（正方形断面）。奥行きを幅と別に推測しない。
- **軸穴の直径**は記録に無い。穴が中心を貫通する構造自体は記載があるので描くが、太さは出所のない
  名目値（illustrative）で、実測ではない。

## 操作

- ドラッグで**縦軸まわり**に回転（実物が軸を通して回された構造なので、その軸に合わせて縦に固定）。
- ホイールで拡大縮小。
- 面をクリックすると、その面の説明が横のパネルに出る。
- `prefers-reduced-motion` 有効時は自動回転を止める。

面ごとの説明文は記事側の作業。ここでは `content/faces.json` を読むだけで、初期は空でよい。空でも
エラーにならず、面の説明欄が出ない（「第 N 面／説明はまだありません」）だけになる。「準備中」は出さない。

## 技術の制約

- **外部のモデルホスティングやアセット CDN に依存しない。** 形状はコードで生成し、バイナリのモデル
  ファイルは同梱しない（three.js のジオメトリを寸法から組む）。
- **WebGL が使えない環境ではフォールバック**する。白画面にせず、記録寸法からの模式図（SVG・正面図）と
  テキスト説明を出す（`src/fallback.ts`）。
- 形状生成に破綻（軸穴が断面に収まらない等）があれば、黙って進めず落とす。

## 次点の対象

同じ枠組み（寸法から起こす）で足せる形にしてある。`src/geometry.ts` の `PrismSpec` を増やす:

- ギョベクリ・テペのT字柱（高さ5.5m、中央柱ペア）
- 押戸石の巨石（高さ5.5m、周囲約15m）

押戸石は層理の向きを面として表現できると記事の論点に直結するが、層理の実測データが無いため初版では
扱わない。

## 開発・ビルド

```bash
pnpm --filter @aw/objects dev       # 開発サーバ（Vite）
pnpm --filter @aw/objects build     # dist/ に静的出力
pnpm --filter @aw/objects test      # 単体テスト（geometry / faces）
```

### デプロイ（Vercel）

- Root Directory: `packages/aw-objects`
- Install Command（リポジトリルートで）: `pnpm install`
- Build Command: `pnpm --filter @aw/objects build`
- Output Directory: `dist`

## 完了状態（検証済み）

実ブラウザ（Chromium）で確認:

1. 四面角柱と軸穴が表示され、縦軸で回転する（自動回転＋ドラッグ、軸は縦に固定）。
2. 模型であることのラベルが初期表示で見える。
3. `content/faces.json` が空でもエラーにならず、面の説明欄が出ないだけになる。
4. WebGL 非対応の環境でフォールバック（模式図＋テキスト）が出る。
